# Apertura compatible de la PWA en compras

## Auditoria y decision

Se revisaron el manifest local y el manifest publico mediante GET el 2026-10-29. Ambos declaran `start_url: '/'`, `display: 'standalone'`, colores e icono existentes, sin `id` ni `scope` explicitos. El endpoint publico es `https://www.mercau.co/manifest.webmanifest`; el acceso sin www redirige a ese origen. Su respuesta tiene `application/manifest+json` y `public, max-age=0, must-revalidate`. La Home publica consultada no enviaba una cabecera CSP. No se modificaron esos encabezados.

El layout registra `/mercau-sw.js` con scope `/`. El worker no implementa almacenamiento de respuestas en su handler fetch y conserva su codigo de push y notificationclick. La deteccion de modo instalado existente en AppLifecycleMetrics e InstallMercau no redirigia el arranque. HomeEntry conserva los alias antiguos; listings conserva su redireccion al directorio.

No se conoce el Computed App Id de cada instalacion anterior. Chrome recomienda comprobar ese identificador antes de establecer un id o modificar start_url. Por ello, la solucion mas conservadora en este corte es **mantener el manifest byte a byte**, incluido su endpoint, inicio, identidad implicita y alcance, y conducir a compras mediante un puente dentro del mismo origen. No se crea un segundo manifest ni una segunda identidad.

Fuente primaria: [identidad PWA y comprobacion del identificador calculado](https://developer.chrome.com/docs/capabilities/pwa-manifest-id). Contexto: [actualizaciones de PWA](https://web.dev/learn/pwa/update), [id en el manifest](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/id).

No hay servicios, APIs, mapas, dependencias, suscripciones o planes nuevos. Las lecturas de vigencia utilizan las conexiones existentes; no se activa facturacion ni se cambian limites. El funcionamiento usa la infraestructura actual.

## Implementacion

- `lib/pwa-launch.ts` resuelve solo la raiz `/` cuando `display-mode: standalone` o `navigator.standalone === true`. El navegador normal conserva la presentacion. `/comprar` sigue disponible desde navegador, sin instalar.
- Un script fijo y autocontenido en el head del layout resuelve el arranque antes de pintar la portada. No interpola datos del usuario ni credenciales en codigo. Oculta temporalmente el documento de entrada y usa `location.replace` hacia `/comprar`, conservando la cadena de consulta y el origen. El documento de destino tiene visibilidad normal.
- La marca de arranque es transitoria en el DOM, no en almacenamiento. Si la navegacion se bloquea sincronicamente se restaura la visibilidad; si queda suspendida, hay una restauracion de respaldo a los ocho segundos. Esa salida permite seguir usando los CTA existentes en vez de quedar permanentemente con un documento oculto. En ese caso de fallo puede reaparecer la Home; no se promete navegacion offline.
- HomeEntry aporta el respaldo para navegacion cliente hacia `/` dentro de una app ya abierta y escucha pageshow/cambios del modo de visualizacion para una ventana convertida en app. Evita iniciar otra redireccion si el puente temprano esta activo. No cuenta la portada como visita cuando esa redireccion temprana esta en curso.
- Las anclas informativas de marketing en la raiz tambien conducen a compras en modo instalado. Los cuatro alias intencionales de directorio, favoritos, cuenta e inscripcion conservan su manejador previo.
- Fragmentos desconocidos y parametros de autenticacion como `code`, `type`, `access_token` o errores quedan excluidos del puente. No se interpreta ni consume una credencial de autenticacion.
- Ninguna ruta distinta de `/` es redirigida por este puente: menus, catalogos, cuentas, negocio, activaciones y seguimiento mantienen su destino. Al reanudar una app ya situada en un menu o pedido no se fuerza el regreso al Inicio.
- No se modifican cookies, localStorage, sessionStorage, autenticacion, carrito, direcciones, pagos, pedidos, QR o Shipday. Tampoco se cambia el worker, su registro, suscripciones push, iconos, splash o campos del manifest.

El script temprano es inline para no introducir una peticion externa ni depender de cargar un recurso nuevo antes del primer dibujo. La politica CSP actual no se debilito. Una futura CSP estricta debe contemplar el nonce/hash de este script; el respaldo React no equivale a la misma prevencion del primer dibujo.

## Pruebas automatizadas

```powershell
node qa/test-pwa-launch.cjs
node qa/test-home-entry.cjs
node qa/test-pwa-boundaries.cjs
node qa/test-presentation-navigation.cjs --home --pwa
node qa/test-presentation-navigation.cjs --home --pwa --production
```

El modo produccion requiere `.next-pwa-build`. Son servidores loopback locales con respuestas de servicios ficticias y escrituras/red operativa bloqueadas, no despliegues. Los modos de app se emulan mediante las senales JS de Chrome; no se instalo una PWA real ni se modifico un perfil privado de navegador.

- Pure/VM: navegador normal, raiz instalada, senal iOS, query, anclas, excepciones de autenticacion, rutas profundas y salidas de navegacion bloqueada/suspendida.
- HomeEntry con hooks y metricas simulados: respaldo cliente y compatibilidad de enlaces previos.
- Navegador: tres contextos por ejecucion (pestana, standalone emulado, iOS emulado). Se comprueba URL y contenido, ausencia de Home visible en el DOM durante el arranque temprano, menu profundo y recarga, respaldo SPA, excepciones de autenticacion y manifest sin cambios.
- Persistencia: cookie HttpOnly ficticia, bytes de una clave de carrito sessionStorage y datos guardados ficticios localStorage. Se siembran una sola vez en una pagina interceptada solo por Playwright, no en cada carga, para no ocultar un borrado. Son centinelas de almacenamiento, no autenticacion real ni restauracion funcional de un pedido.
- Regresion: ocho recorridos de Home/listados/menu/catalogo con Atras/Adelante, anclas, ayuda y alias en cada modo de compilacion. No se envian pedidos.
- Typecheck, lint y build: ejecutar sobre el mismo corte; las advertencias previas de img/hooks se mantienen sin refactorizar modulos ajenos.
- Integridad: 156 archivos operativos intactos respecto al baseline inicial; solo Home (hito anterior) y layout (puente autorizado) se excluyen explicitamente. Manifest, worker, registro del worker, presentacion V3, imagenes y componentes de carrito/pedidos/pagos quedan sin cambios. El baseline y cortes anteriores no se sobrescriben.

Evidencias: `outputs/pwa-entry/pwa-results.json`, `outputs/pwa-entry/results.json`, y los equivalentes bajo `outputs/pwa-entry-production/`. La prueba del registro del worker normaliza CRLF/LF al compararlo con Git; no se cambio su contenido.

Resultado del corte: aprobados los seis contextos de senales emuladas (tres en desarrollo y tres en produccion local), los 16 recorridos de regresion, unitarios/VM, typecheck, lint y build. Tambien se comprobo la conversion de ventana mediante cambio de media query; pageshow se prueba con un callback simulado, no como restauracion real del sistema operativo. Persisten solo las advertencias anteriores de img/hooks. No hay instalaciones reales verificadas en este hito.

## Comprobacion real pendiente tras autorizar publicacion

No se consideran actualizadas las instalaciones existentes por estos tests. El puente requiere que llegue el HTML/JS nuevo; una app suspendida o una captura anterior del sistema puede seguir mostrando la version previa hasta recargar o volver a abrir con red.

Registrar modelo, sistema, navegador/version, origen y si es WebAPK, web app iOS o un simple acceso directo. No copiar credenciales a reportes.

1. En una instalacion existente, sin desinstalar ni borrar datos, cerrar y abrir el icono con red. Verificar compras y ausencia de portada; comprobar la sesion propia autorizada.
2. Repetir en una instalacion nueva despues del despliegue aprobado; comprobar que no se ofrece/crea otra identidad accidental y comparar Computed App Id/manifest_id en Chrome cuando sea posible.
3. En iPhone, verificar que el icono abre como app web. Un acceso que abre una pestaña normal no aporta necesariamente senal standalone y seguira mostrando la portada. No usar una deteccion por user agent para forzarlo.
4. Comprobar carrito y direccion con datos de prueba, sin confirmar pedidos; probar recarga, suspension y cierre completo. El carrito actual usa sessionStorage por negocio para pedidos live: este corte conserva ese mecanismo, no lo convierte en persistencia permanente entre sesiones del sistema operativo.
5. Abrir enlaces directos de menu, catalogo y seguimiento autorizado, tambien desde una app ya abierta. No generar despachos ni pushes reales para esta comprobacion sin autorizacion.
6. Verificar pestaña de navegador `/` como portada y navegador `/comprar` como compras. Probar conexion lenta y fallo de navegacion. No se promete uso offline ni se alteran capturas/splash controlados por el sistema operativo.

No se inspecciono el identificador calculado de instalaciones historicas ni se certifico propagacion del cambio en Android/iPhone reales. Mantener los valores del manifest evita introducir un identificador nuevo a ciegas; no fusiona posibles duplicados previos ni migra origenes.
